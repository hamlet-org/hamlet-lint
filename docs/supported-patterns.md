# Supported automatic-propagation patterns

This page shows code shapes Hamlet Subtractor can prove automatically. Each
example states what the PPX learns and what remains in the result.

## Small shared definitions

The error examples use a finite row with three independent leaves:

```ocaml
module Errors = struct
  type missing = [ `Missing ]
  type timeout = [ `Timeout ]
  type unavailable = [ `Unavailable ]
  type all = [ missing | timeout | unavailable ]
end

let source : (string, Errors.all, Hamlet.never) Hamlet.t =
  Hamlet.Combinators.fail (`Missing : Errors.all)
```

The service examples assume services generated by `ppx_hamlet` and a concrete
implementation:

```ocaml
[%%hamlet.service
module type Logger = sig
  val log : string -> (unit, 'errors, 'requirements) Hamlet.t
end]

module Logger_live = Logger.Make (struct
  let log _ = Hamlet.Combinators.return ()
end)
```

## Inline handlers

A direct `catch` with an inline function is supported:

```ocaml
let result =
  Hamlet.Combinators.catch source ~handler:(function
    | #Errors.missing -> Hamlet.Combinators.return "missing"
    | [%hamlet.propagate_e.auto] -> .)
```

`Errors.missing` is removed. The result can still fail with `timeout` or
`unavailable`.

Pipeline syntax means the same thing:

```ocaml
let result =
  source
  |> Hamlet.Combinators.catch ~handler:(function
       | #Errors.missing -> Hamlet.Combinators.return "missing"
       | [%hamlet.propagate_e.auto] -> .)
```

The handler must be written at the call site so the PPX can connect the owner,
input, patterns, and marker.

## Complete error arms

A generated `#Path` covers one complete error leaf:

```ocaml
| #Errors.missing -> Hamlet.Combinators.return "missing"
```

An alias is also supported when recovery code needs the value:

```ocaml
| #Errors.timeout as error -> report_and_recover error
```

An unguarded arm removes its leaf. A guarded arm is valid OCaml and remains
supported, but it does not remove the leaf because its guard may be false:

```ocaml
| #Errors.timeout as error when retryable error -> retry error
```

In this last example, the generated fallback still forwards `timeout`.

## Complete requirement arms

`Tag.give` removes the service when it uses the witness bound by the pattern:

```ocaml
| #Logger.Tag.r as witness ->
    Logger.Tag.give witness (module Logger_live)
```

`Dispatch.need` explicitly keeps the service in the output:

```ocaml
| #Logger.Tag.r as witness -> Hamlet.Dispatch.need witness
```

The automatic arm generates equivalent `Dispatch.need` cases for requirements
not mentioned above it.

## Closed and explicit rows

A closed row is complete by construction:

```ocaml
let source :
    (string, [ `Missing | `Timeout ], Hamlet.never) Hamlet.t =
  make_source ()
```

An explicit occurrence also states the whole universe:

```ocaml
let source =
  (make_source () :
    (string, [%hamlet.te Storage], Hamlet.never) Hamlet.t)
```

The automatic marker may use either value because the type itself excludes
unknown leaves.

## Independently generalized values

OCaml may print an exported value with an open lower bound:

```ocaml
(* producer.mli *)
val source :
  (string, [> `Missing | `Timeout ], Hamlet.never) Hamlet.t
```

`[> `Missing | `Timeout ]` normally means “at least these two tags.” It does
not, by itself, prove that no third tag exists.

An exported value has a reusable type scheme. At each use, OCaml makes fresh
type variables for that scheme. The resolver does the same on a private copy
and asks: can the fresh row tail be set to “no additional tags” without
changing any type variable owned by the surrounding program?

If yes, this use is exact at `Missing` and `Timeout`. Only the temporary copy is
closed; the exported declaration and caller types are unchanged. This is the
common case for a value whose definition chose its own effects:

```ocaml
(* producer.ml *)
let source = Hamlet.Combinators.fail `Missing
```

If the row is tied to a function argument or another caller-owned value,
closing it would also restrict the caller. That case is refused and shown in
[Rows chosen by callers](./refused-patterns.md#rows-chosen-by-callers).

## Concrete local builders

The practical rule is:

> The resolver must be able to determine the returned effect rows from the
> builder's body, without learning them from an argument or mutable value.

A directly called unit builder satisfies that rule:

```ocaml
let build () =
  Hamlet.Combinators.fail (`Missing : Errors.missing)

let result =
  Hamlet.Combinators.catch (build ()) ~handler:(function
    | #Errors.missing -> Hamlet.Combinators.return ()
    | [%hamlet.propagate_e.auto] -> .)
```

The body itself contains the real Hamlet `fail`, so the error row does not
depend on `()` or on the call site.

A builder may take ordinary arguments when those arguments do not determine
its effect row:

```ocaml
let load path =
  if String.equal path "" then Hamlet.Combinators.fail `Missing
  else Hamlet.Combinators.fail `Timeout
```

The returned row is always the finite set `Missing | Timeout`; `path` chooses
which branch runs, not which type of effect the function is allowed to return.

## Verified first-class service modules

A generated summon returns a first-class module. This builder is supported:

```ocaml
let build () =
  let open Hamlet.Combinators in
  let* (module Logger) = Logger.Tag.summon in
  let* () = Logger.log "starting" in
  return ()
```

`ppx_hamlet` inserts the package type on `(module Logger)` and lowers
`Logger.Tag.summon` to Hamlet's primitive summon operation. The resolver then
checks three concrete facts:

1. the summon key and tag identify the generated `Logger` service;
2. the unpacked module kept the package type inserted by `ppx_hamlet`;
3. `Logger.log` resolves to a Hamlet computation through that same module.

Those links prove that `build ()` requires `Logger`. They do not make arbitrary
first-class modules trusted.

## Recovery code may add effects

Recovery expressions are measured and included in the output certificate:

```ocaml
let first =
  Hamlet.Combinators.catch source ~handler:(function
    | #Errors.missing -> Hamlet.Combinators.fail `Recovery_failed
    | [%hamlet.propagate_e.auto] -> .)

let second =
  Hamlet.Combinators.catch first ~handler:(function
    | `Recovery_failed -> Hamlet.Combinators.return "recovered"
    | [%hamlet.propagate_e.auto] -> .)
```

`first` can fail with `timeout`, `unavailable`, or `Recovery_failed`. The second
automatic marker receives that complete output and may handle the newly added
error.

Recovery code may also summon a service. A later automatic `provide` marker can
consume that requirement because certificates track errors and requirements
separately.

## Linear marker chains

There is no two-marker limit. A later marker can handle old leaves and leaves
introduced between markers.

The following example starts with `Old_a | Old_b | Old_c`:

```ocaml
module Chain_errors = struct
  type old_a = [ `Old_a ]
  type old_b = [ `Old_b ]
  type old_c = [ `Old_c ]
  type old = [ old_a | old_b | old_c ]
  type new_one = [ `New_one ]
  type new_two = [ `New_two ]
  type after_first = [ old_b | old_c | new_one ]
  type after_second = [ old_c | new_one | new_two ]
end
```

The first marker handles `Old_a`:

```ocaml
let first =
  source
  |> Hamlet.Combinators.catch ~handler:(function
       | #Chain_errors.old_a -> Hamlet.Combinators.return "old A"
       | [%hamlet.propagate_e.auto] -> .)
```

Hamlet's `chain` uses one shared error-row type for both computations. The
explicit upcast below declares the intended combined row before `let*` adds
`New_one`:

```ocaml
let with_new_one =
  let first =
    (first :>
      (string, Chain_errors.after_first, Hamlet.never) Hamlet.t)
  in
  let open Hamlet.Combinators in
  let* _ = first in
  (fail (`New_one : Chain_errors.new_one) :>
    (string, Chain_errors.after_first, Hamlet.never) Hamlet.t)
```

The next marker handles the old `Old_b` leaf and its recovery adds `New_two`:

```ocaml
let second =
  with_new_one
  |> Hamlet.Combinators.catch ~handler:(function
       | #Chain_errors.old_b ->
           (Hamlet.Combinators.fail
              (`New_two : Chain_errors.new_two)
             :>
             ( string,
               Chain_errors.after_second,
               Hamlet.never )
             Hamlet.t)
       | [%hamlet.propagate_e.auto] -> .)
```

A third marker may now handle `New_one`:

```ocaml
let third =
  second
  |> Hamlet.Combinators.catch ~handler:(function
       | #Chain_errors.new_one -> Hamlet.Combinators.return "new one"
       | [%hamlet.propagate_e.auto] -> .)
```

The final error row is exactly `Old_c | New_two`.

The same rule applies to requirements. For example: provide `Logger`, use
`let*` with a verified `Metrics.Tag.summon`, provide the older `Clock`, then
provide the newly introduced `Metrics`. Each marker receives the exact output
of the previous marker plus the proven summon contribution.

## Identity checks

Printed names are not evidence:

```ocaml
let fail error = Error error
```

This local `fail` is not `Hamlet.Combinators.fail`. The resolver compares the
compiler identity of the resolved declaration, so lookalike names cannot enter
an exact proof.

For the opposite cases, continue with [Refused patterns](./refused-patterns.md).
